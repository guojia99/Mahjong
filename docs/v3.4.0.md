## 研发一个小游戏 "雀谜"
- 前端生成一个谜题，一共13张手牌以及一张手摸牌。
  - 谜题有两种类型  
    - 一种是可胡牌型
      - 可胡牌型需要给出自家的顺位、场风、当前宝牌、是否可荣胡。
    - 一种是不可胡牌型。
      - 不可胡牌型是完全无法荣胡的，即至少还有1向听数。
      - 不可胡牌型需要为玩家提供这个牌谱的向听数。
  - 基本流程
    - 选定场风自、风生、和了情况
    - 生成一副和牌（13张+1张和了牌，门清状态，不含杠子）
    - 玩家输入手牌
      - 核查是否为和牌（否则输入无效）
      - 核查荣和类题目是否有役（否则输入无效）
      - 均满足则消耗一次次数
      - 如果是无法胡牌的类型，则反向检查即可
    - 输入与答案中
      - 牌面和位置均正确的牌标绿（如第一张牌是1m，玩家输入1m标绿）
      - 牌面正确但位置不对标黄（如第一张牌是1m，玩家在其他位置输入1m标黄）
      - 不含该牌面/该牌面数量超出的标黑（如牌型不含中，输入的中标黑；牌型中仅有二张中，输入的第三张中标黑）
  - 玩家有N次机会可以进行猜牌谱，分为五个等级
    - 困难 4次 
    - 进阶 5次 
    - 中等 6次
    - 普通 7次  
    - 简单 8次
  - 玩家在开始时就需要选择谜题类型和难易程度
  - 谜题默认不带赤宝牌，所以生成时忽略0p、0m、0s
  - 谜题有默认顺序，即
    - 1m~9m 万
    - 1p~9p 饼
    - 1s~9s 条
    - 1z~7z 字牌: 东南西北白发中
  - 而选手输入不需要排序，由选手自己按顺序输入

- 前端实现
  - 需要能够保存在浏览器中的历史谜题
  - 输入有两种模式
    - 点击输入，类似工具中的牌输入器即可，按照点击顺序将对应的牌添加到当前剩余的格子中
    - 拖拽输入，可以在对应的牌格中，拖拽牌到对应的铺子上，同事手牌和摸牌都可以被拖拽
      - 注意，上一次提交的无法拖拽，而是当前的才可以拖拽
  - 清空，玩家可以清空当前手牌重新输入
  - 注意，每张牌最多四张，如果宝牌使用了，就默认少一张。
  - 支持进入全屏模式。
  - 需要有游戏引导。
